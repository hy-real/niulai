# evals —— 任务级回归集（P3.5）

**已建成**：10 条确定性断言的任务清单 + 运行器。跑一次就知道改动有没有让 agent 变差。

与 `packages/niulai/tests` 的分工：

| | tests/ | evals/ |
| --- | --- | --- |
| 验证什么 | 内核机制（回灌、熔断、裁剪、协议转换） | 端到端行为（选没选对工具、有没有越界） |
| LLM | mock，无网络 | 真模型，要 Key |
| 何时跑 | 每次改动（秒级） | 改 prompt / 工具 schema **前后各一次** |

## 用法

```bash
.venv/Scripts/python -m evals.run            # 跑全部
.venv/Scripts/python -m evals.run quote      # 只跑 id 含 "quote" 的
.venv/Scripts/python -m evals.run --list     # 列出任务清单
.venv/Scripts/python -m evals.run --verbose  # 通过的也显示说明
```

退出码：全过 0，有失败 1 —— 可以接进 CI 或改动前后的脚本对比。

## 断言类别（对应任务清单见 `tasks.py`）

| 类别 | 断言示例 |
| --- | --- |
| 工具选择 | 问"茅台多少钱"必须调 `stock_quote`，且 `symbol` 参数原样携带 |
| 反向路由 | 闲聊不许触发任何数据工具 |
| 拒答边界 | 问"该不该买"必须有回答，但不得出现"建议买入"等确定性表述 |
| 预算 | 轮数 ≤ 上限（空转即失败） |
| 自愈 | 不存在的股票代码：收敛、有回答、不空转 |
| 落盘链路 | 半年 K 线必然超限：上下文里应是"摘要 + artifacts/ 路径"，不是全量 |

设计原则：**只做确定性断言**（调没调对工具、轮数、禁用词），不上 LLM-as-judge ——
评判本身不稳定，回归集要的是可复现。参数断言用子串不用全等（模型可能传
`600519` 也可能传 `sh600519`，只要行为对就不卡具体写法）。

解读结果的心法：**断言是确定性的，模型表现是概率的。** 偶发失败先重跑一次；
同一任务反复失败才是真回归。每条任务照常落 trace，失败时可 `niulai replay` 归因。

结果有三种标记：

- `PASS` / `FAIL` —— 判定通过 / 回归
- `SKIP` —— 数据源被限流等外部抖动导致无法判定，**不计入通过率**（尺子只量 agent，
  不量东财的心情；退出码也不因 SKIP 而非零）

Ctrl-C 中断时不裸奔 traceback：已完成的任务照常打分，汇总后以 130 退出。
